# 音樂調性分析器

## Proposal Report

### 動機與目標
<!-- 說明為什麼想做這個專題 -->
從小到大玩音樂的過程中，抓曲子及特定段落的調性都是很重要的部分，然而，調性屬於樂理的範疇，雖然可以透過學習來慢慢習得，但要是能透過程式幫忙抓調性，應該會是一個很方便的工具吧！ 

本專案的目標，就是寫出能夠讀取音訊檔，分析裡面各音高的強度，進而判斷其調性的工具。
### 預期功能
<!-- 列出預計實作的功能 -->
兼容各種市面上常見的音訊(eg. MP3, M4A, WAV)作為輸入，並且允許時間在一個區間內，約在一個小節到一整首5分鐘的歌曲。根據輸入的內容，判斷最可能的調性並輸出。

介面我預計用CLI在終端機上跑，不過若是有多餘的創作能量，我會嘗試升級成GUI。

### 競品比較 
市面上已有如 Chordify、Mixed In Key 等成熟的商業軟體，但本專案與其具備以下核心差異：
1. **分析粒度與靈活性**：多數現有工具要求對「整首歌曲」進行分析，較難處理複雜的曲中轉調，比如說周董的楓，在第二次副歌後向上提升了半個音，這樣會相當程度的影響分析軟體的成效；本系統主打「區間切片分析」，使用者可指定特定小節或時間段落進行特徵萃取，專注於局部的調性變化。
2. **演算法透明度**：商業軟體多為Black Box，僅輸出最終結果；本系統會在終端機清楚印出輸入特徵與 24 個大小調樣板的「皮爾森相關係數 (Pearson Correlation)」，讓使用者能直觀評估演算法的信心水準，具備較高的教育與學術驗證價值。
3. **新觀念與技術的引進** 這些商業軟體大多都已行之有年，然而`Krumhansl-Schmuckler`這個調性分析權重樣板是相當近期才有的東西，我測試了一下發現相較原本二元式的樣板，對主音提高權重的確能改善準確度，這些是相對於其他商業軟體，在數學計算上具備的巨大優勢。

### 使用技術
<!-- 使用的語言、框架、工具等 -->
本專案預計使用 python實作，由於其搭載讀取音檔、時域轉頻域的相關函式等。 
針對專案功能的組成，我目前大致畫分成四個區間：
 
1.讀取&前置處理
 
架設環境並熟悉讀取所需的套件，我預計使用librosa裡面載入音檔，並做後續的處理 
 
2.核心特徵抓取
 
首先呼叫套件處理傅立葉轉換，才得以轉換成頻譜資料做使用，接下來需要過濾鼓聲及其他雜訊，並創作函式將音符的頻率範圍做資料分群，將這些音訊對應到十二個半音上，產出十二維度的能量矩陣。 
 
3.調性分析
 
建立總共24個大小調的權重樣板，並且將能量矩陣對其做相似度評比（這裡預計用內積來處理，抓取最相似的組成）
 
### Prototype預計可驗證內容

 

 
### Prototype 預計可驗證內容
本階段的最小可行性方案 (MVP) 旨在驗證系統核心邏輯的可行性，主要聚焦於以下三點：
1. **跨格式讀取能力**：驗證系統能否成功載入並解碼經過壓縮的常見音訊格式 (如 MP3)。
2. **特徵轉換邏輯**：驗證 STFT 與 12 半音特徵萃取演算法，能否正確且穩定地將時域訊號收斂為二維矩陣。
3. **基礎調性預測準確度**：透過無雜訊、無曲中變調的單一樂器 (如純鋼琴) 音檔作為基準控制組，驗證樣板比對演算法能否順利輸出符合預期的調性，並具備合理的統計信心水準。

## Prototype Report

### 目前進度
目前已成功建置CLI版本的最小可行性系統，並完成以下開發節點：
* **前置處理模組**：透過`Audio_processor`實作能夠兼容 MP3 檔案的輸入流，並統一將音訊標準化為單聲道、特定取樣率(我目前開在22050 Hz)的 Numpy 陣列。
* **特徵工程實作**：成功將音訊切片並提取出12個半音的能量矩陣，完成時域至頻域的轉換。
* **演算法整合與測試**：實作 `Krumhansl-Schmuckler`調性分析模型。在輸入純鋼琴音檔的基準測試中，系統成功印出 24 個大小調的相關係數，並以約 0.68 的信心指數準確預測出該段音訊的調性。

### 遇到的困難
1. **音訊解碼與依賴環境衝突**：初期開發時遭遇底層解碼器無法讀取 MP3 格式的問題。最後專案的目標，就是要能兼容多種音檔，盤點系統依賴環境後，透過更新處理函式庫與引入更強的解碼工具，解決輸入流格式限制。
2. **演算法精確度盲區**：原先預計使用的單純「餘弦相似度」容易受到音訊絕對能量或基底雜訊的干擾，比如他這裡唱的特別大聲，不應該影響到權重，但相對小聲的段落，卻對模型產生更大的影響。重新檢視數學模型後，我後來決定在比對前將輸入特徵與樣板皆進行`Z-score`標準化，並且改用`Pearson Correlation`來處理，成功消除音量干擾並提升鑑別度。

### 下一步計畫
1. **強化抗噪與髒資料處理能力**：五月天的歌裡面時常摻雜冠佑的Hi-hat，不影響調性但會影響模型，下一步我想著手研究將打擊樂等不具明確音高的雜訊進行過濾或弱化，讓系統比較能處理流行音樂那種真實資料。
2. **實作效能分析與比較**：配合專案目標調整，我目前有兩種想法：
第一種是針對樣板相似度計算的部分，可以嘗試實作「基礎迴圈」與「Numpy 矩陣運算」兩種不同演算法，量化比較一下執行時間跟性能。
第二種是針對特徵矩陣的時間軸加總，我目前是直接壓成一維矩陣讓系統去跑，但寫一個迴圈，Frame by Frame讀STFT產出的幾千個時間幀的特徵陣列再累加數值，應該也是一個可行的選擇。
3. **使用者體驗 (UX) 升級**：規畫逐步引入更完善的防呆機制，防止抽象使用者，然後做一個GUI介面，讓使用起來更貼近一個日常工具APP的體驗。
